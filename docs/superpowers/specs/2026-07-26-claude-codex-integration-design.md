# Claude Code × Codex 連携 設計書

作成日: 2026-07-26
対象環境: Windows 11 ネイティブ（PowerShell）/ Node v24 / npm 11

## 目的

Claude Code を司令塔（メイン）として使いつつ、Codex が得意な作業を Codex に委任し、
両者の強みを活かす。指示・オーケストレーションは Claude Code 側から行う。

## 方針（採用案：案A）

`codex exec`（非対話モード）を Claude Code から Bash 経由で呼び出す。
`/codex` スラッシュコマンドでラップし、委任基準は CLAUDE.md に明文化する。

- MCP 化（案B）は将来の発展候補。まずは透明性と Windows 安定性を優先し案Aで実装する。

## 全体フロー

```
ユーザー ──指示──▶ Claude Code(司令塔)
                     │
                     ├─ 自分でやる（大半のタスク）
                     │
                     └─ Codex向きと判断 ──▶ /codex コマンド
                                              │ codex exec を Bash で実行
                                              ▼
                                        Codex がリポジトリ内で作業
                                              │
                     ◀── 結果/差分を回収 ──────┘
                     │
                     └─ Claude が差分をレビュー → ユーザーに報告
```

Codex は Claude Code と同じ作業ディレクトリ（リポジトリ）で実行するため、
ファイルの文脈は共有される。作業結果は git 差分として回収・レビューする。

## 構成要素

### 1. Codex CLI の導入と認証
- `npm i -g @openai/codex` でインストール
- `codex login`（ChatGPT 有料プランのログイン）で認証
- `codex --version` で疎通確認

### 2. `/codex` スラッシュコマンド
- 役割: Claude が `codex exec "<タスク>"` を非対話で実行するラッパー
- デフォルト挙動: **実行役モード（ファイル編集可 / workspace-write）**
  - Codex がリポジトリ内のファイルを実際に編集する
  - 作業後、**Claude が必ず git 差分をレビュー**してからユーザーに報告する
- 読み取り専用モード: フラグで切替。レビュー・セカンドオピニオン・分析のみ（ファイル非変更）
- 実行結果（標準出力）と変更差分（git diff）の両方を回収して Claude に返す

### 3. CLAUDE.md への委任ルール追記
Claude が「いつ Codex に任せるか」を自動判断できるよう、基準を明文化する。

初期の委任基準（後で調整可）:
- Claude が詰まったバグの独立したセカンドオピニオンが欲しいとき
- 仕様が明確で自己完結した実装タスクの切り出し（並行処理・使用量節約）
- 別モデルの視点が欲しい設計・レビュー

## 動作モードと安全性

- デフォルト = 実行役（workspace-write）。作業後に Claude が差分レビュー必須。
- 読み取り専用モード = read-only。ファイル変更なし、提案のみ。
- Codex の作業は git 管理下。気に入らなければ差分を破棄可能。
- ネットワーク遮断などサンドボックスの細かい挙動は、Windows ネイティブで実際に
  動かして確認しながら詰める（フラグ名・既定値は導入時に検証）。

## エラーハンドリング

- Codex 未インストール / 未ログイン: `/codex` 実行前に疎通を確認し、失敗時は
  導入・ログイン手順を案内する。
- Codex がタスク失敗 / 差分なし: 標準出力をそのまま提示し、Claude が原因を判断。
- 差分が意図と異なる: Claude がレビュー段階で検出し、破棄または修正してから報告。

## スコープ外（YAGNI）

- 案B（MCP サーバー化）の実装 — 将来の発展候補として記録のみ
- 2つを完全並行運用する worktree 分離運用 — 今回の目的（Claude が指示）に不要
- CI 等の自動化への組み込み — 今回は手動連携の確立に集中

## 成功基準

- Claude Code のセッション内から `/codex` で Codex にタスクを委任できる
- Codex がリポジトリ内で作業し、その差分を Claude がレビューして報告できる
- CLAUDE.md の基準に沿って Claude が委任を判断できる
